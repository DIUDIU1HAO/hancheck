# hancheck：中文项目代码体检

## 什么时候用

在下列任一情况下，你应该在给出"已完成"之前先跑一次：

- 你（或用户）刚刚生成了中文项目的代码、配置或文档
- 用户报告"本地能跑、服务器报错"、"缩进错误"、"JSON 解析不了"、"满屏乱码"
- 准备提交代码、开 PR、发布版本
- 项目里有中文注释、中文文案、中文路径

**不要**在每次改文件后都跑——它的定位是交付前的门禁，不是保存时的语法检查。

## 怎么跑

```bash
pip install hancheck
hancheck .                       # 全量体检
hancheck --fail-level warning .  # CI 门禁
hancheck --json .                # 需要结构化结果时
hancheck --html report.html .    # 需要给用户看报告时
```

如果项目里已经有 `.hancheckignore`，会自动生效。

## 结果怎么处理

按这个顺序处理，不要一次全改：

1. **error 必须处理**。`CN001` 全角标点在代码结构里、`CN003` 全角空格、`CN005` GBK 编码，这三类会直接导致程序跑不起来。
2. **warning 需要判断**。`CN006`/`CN007`/`CN008` 是敏感信息，不要自动替换成别的号码，要与用户确认脱敏方式（通常替换为 `13800138000` 这类公开假号，或改为从环境变量读取）。
3. **info 可以放过**。`CN010` 中文标识符在存量项目里很常见，除非用户明确要求否则不要批量重命名。

## 修复的边界

`hancheck --fix` 只修能确定语义的字符。**它不会修改字符串内的中文标点、中文变量名和敏感信息**，这是刻意的设计，不要试图绕过。

如果 `--fix` 之后仍有 error，说明需要人工判断；此时应把具体位置和原因告诉用户，而不是自己猜着改。

## 常见误报的处理

- 注释里的中文标点是**正常写作**，工具已经放过，不要再去改注释。
- README 里的终端输出块（```text）不会被当作代码，无需处理。
- 若某条规则在用户的业务场景下确实不适用，用 `--ignore CN0xx` 或在 `.hancheckignore` 里排除路径，**不要**修改规则源码。
